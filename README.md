## What This Project Builds

A complete, end-to-end implementation demonstrating how four engineering
disciplines work together on AWS:

| Module | What It Does |
|--------|-------------|
| **Cloud Engineering** | VPC, private subnets, IAM roles, KMS keys, S3 data lake — all in Terraform |
| **Security Engineering** | CloudTrail, AWS Config rules, CloudWatch alarms, IAM Access Analyzer |
| **Data Engineering** | Synthetic event generation → validation → transformation → quality reporting |
| **AI Engineering** | Isolation Forest anomaly detection → risk scoring → explainable alerts |

## Security Controls Implemented

| Category | Controls |
|----------|---------|
| Identity | IAM roles + temporary credentials; no long-lived keys; MFA conditions; IAM Access Analyzer |
| Encryption | KMS CMKs × 4 (one per data zone); automatic rotation; SSE-KMS on all S3 |
| Network | VPC with private subnets; Security Groups; VPC Endpoints (S3, SSM); no public workloads |
| Audit | CloudTrail (multi-region, log validation, KMS-encrypted); 8 Config rules |
| Monitoring | 5 CIS-aligned CloudWatch alarms; SNS notifications; CloudWatch dashboard |
| Data | Schema validation; quarantine; data quality scoring; no real PII in dataset |
| AI | Advisory-only alerts; no auto-remediation; disclaimer on all outputs |
| Code | No credentials in code; secrets in Secrets Manager / env vars; .gitignore enforced |

## AWS Deployment (Requires Explicit Approval)

> **Do NOT deploy until you have read `cloud_engineering/deployment.md`.**

Prerequisites before deploying:
1. Install Terraform (`choco install terraform` or download from hashicorp.com)
2. Configure AWS credentials (`aws configure` or IAM role)
3. Confirm this is a sandbox account (`aws sts get-caller-identity`)
4. Review the cost estimate: **~$52/month** (mainly NAT Gateway)
5. Copy `terraform.tfvars.example` to `terraform.tfvars` and fill in values

```powershell
cd infrastructure/terraform
terraform init
terraform validate
terraform plan -out=tfplan
# READ THE PLAN — then:
terraform apply tfplan
```

**Teardown:**
```powershell
terraform destroy
```

## What Is NOT Implemented (Production Gaps)

| Gap | Why | Production Remediation |
|-----|-----|----------------------|
| GuardDuty disabled | Cost | Enable before production; ~$4/1M events |
| Security Hub disabled | Cost | Enable; subscribe to CIS standard |
| Single AWS account | Demo scope | Use AWS Organizations + multi-account |
| Local Terraform state | Demo scope | Use S3 backend + DynamoDB lock |
| No WAF | No public endpoint | Add when adding API Gateway or ALB |
| AI trained on synthetic data | Demo scope | Retrain on 3+ months real events |
| No formal IR runbook | Demo scope | Create + test with annual tabletop |
| VPC Flow Logs disabled | Cost | Enable per investigation window |

## Next Steps for Production Hardening

1. **Enable GuardDuty** in all regions → integrate findings into Security Hub
2. **Enable Security Hub** → subscribe to CIS AWS Foundations Benchmark
3. **Migrate to AWS Organizations** → implement SCPs; separate prod/non-prod accounts
4. **Move Terraform state to S3 + DynamoDB** → encrypted, version-controlled
5. **Add AWS WAF** → if any public-facing API Gateway or ALB is added
6. **Retrain AI model** → on 90+ days of authorized real CloudTrail events
7. **Implement IR runbook** → test with annual tabletop exercise
8. **Enable VPC Flow Logs** → export to S3 (cheaper than CloudWatch)
9. **Add Macie** → for S3 bucket sensitive data discovery
10. **Implement CI/CD pipeline** → include Checkov, Bandit, and DAST scanning
